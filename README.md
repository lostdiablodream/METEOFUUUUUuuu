# МетеоЦентр — дашборд погоды и климата

Тематическая интерактивная панель управления UI-компонентами (ООП, ES6-модули, чистый JS без сборки).

Тема: **«Погода и климат»**. Виджеты:

| Виджет | Источник данных | Тип |
|---|---|---|
| Погода | Open-Meteo Forecast API (`api.open-meteo.com`) | сторонний API, без ключа |
| Качество воздуха | Open-Meteo Air Quality API (`air-quality-api.open-meteo.com`) | сторонний API, без ключа |
| Дневник наблюдений | собственный mock-API `GET/POST/PATCH/DELETE /api/notes` | локальный JSON-endpoint (БД — `db.json`) |
| Цитата о погоде | массив внутри класса | локальные данные |

## Запуск

Требуется Node.js ≥ 18 (внешние зависимости отсутствуют).

```bash
npm start          # или: node server.js
# открыть http://localhost:3000
```

Сервер (`server.js`) одновременно:

1. раздаёт статику (`index.html`, модули `js/`, стили `styles/`);
2. предоставляет JSON API `/api/notes` поверх файла-БД `db.json` (мок-данные уже заполнены).

Виджет «Дневник наблюдений» работает только при запуске через `server.js` (нужен API).
Остальные виджеты работают и на любом статическом хостинге.

## API `/api/notes`

| Метод и путь | Тело | Ответ |
|---|---|---|
| `GET /api/notes` | — | `200` массив записей |
| `POST /api/notes` | `{ "text": "…" }` (1–200 символов) | `201` созданная запись |
| `PATCH /api/notes/:id` | `{ "done": true }` и/или `{ "text": "…" }` | `200` обновлённая запись / `404` |
| `DELETE /api/notes/:id` | — | `200 { "ok": true }` / `404` |

Запись: `{ id, text, done, createdAt }`. Хранение — файл `db.json`, перезаписывается целиком.

## Архитектура

```
index.html            — страница, подключает main.js как type="module"
main.js               — точка входа: экземпляр Dashboard, обработчики кнопок тулбара
server.js             — node:http: статика + JSON API /api/notes (без зависимостей)
db.json               — файл-БД с мок-наблюдениями
js/
├── api.js            — fetchJSON: fetch + таймаут + объединение AbortSignal
├── UIComponent.js    — абстрактный базовый класс виджета
├── Dashboard.js      — коллекция виджетов, addWidget(type) / removeWidget(id)
├── WeatherWidget.js  — UIComponent + Open-Meteo Forecast
├── AirQualityWidget.js — UIComponent + Open-Meteo Air Quality
├── NotesWidget.js    — UIComponent + CRUD к /api/notes (делегирование событий)
└── QuoteWidget.js    — UIComponent + локальный массив цитат
styles/
├── main.css          — layout страницы, сетка дашборда (CSS Grid)
└── components.css    — стили виджетов и состояний
```

### ООП

- **Инкапсуляция** — состояние виджета (город, список записей, текущая цитата) хранится в свойствах экземпляра; DOM и слушатели создаются внутри класса.
- **Наследование** — все виджеты наследуют `UIComponent` (`render()`, `destroy()`, `toggleMinimize()`, `close()`, хелперы состояний `showLoading/showError/showEmpty`, `_request`, `_listen`, `_setInterval`).
- **Полиморфизм** — `Dashboard` работает с виджетами через общий интерфейс (`render/mount/destroy`); реестр типов `WIDGET_TYPES` позволяет добавить новый виджет одной строкой, не меняя код дашборда (open/closed).

## Проверка качества (чек-лист)

- Каждый API-виджет показывает состояния **загрузка / ошибка (с «Повторить») / пусто / успех**.
- Устаревший запрос отменяется: `_request()` вызывает `abort()` предыдущего `AbortController`; `AbortError` не рисует ошибку.
- Данные API считаются недоверенными: рендер только через `textContent`/`createElement`, `innerHTML` не используется.
- API-ключи не нужны (Open-Meteo без ключа), секретов в репозитории нет.
- `destroy()` удаляет слушатели (`removeEventListener`), очищает интервалы автообновления, отменяет незавершённый запрос, убирает элемент из DOM.
- Управление с клавиатуры: все действия — нативные `button/select/input/form`, видимый `:focus-visible`, `aria-label` на иконочных кнопках. Перетаскивание не реализовано, поэтому кнопочная альтернатива не требуется.
- В списке наблюдений — делегирование событий (один слушатель на список).

## Ограничения

- Open-Meteo (бесплатный тариф): ~10 000 запросов/сутки, данные обновляются на стороне провайдера с задержкой; автообновление виджетов — раз в 10–15 минут.
- Список городов задан константой в виджетах (геокодинг не используется).
- `db.json` — однофайловое хранилище без конкурентного доступа и авторизации; для учебного проекта достаточно.
- При раздаче фронтенда статическим хостингом (GitHub Pages и т.п.) «Дневник наблюдений» не работает — нужен Node-сервер.

## Оформление (design-skills)

Дизайн собран по skills из `design-skills/skills/` (архив — `design-skills.tar.gz`):

- **frontend-design-principles + app.md** (основной, дашборды): доменные токены (`--ink`, `--canvas`, `--accent` — «штормовой сланец / снег / ясное небо»), плоские поверхности — глубина только рамками, без теней; радиусы 4/6/10; один акцент; табличные цифры (`tabular-nums`) для всех показаний.
- **frontend-design (Anthropic)**: убраны шаблонные приёмы — градиентный hero-хедер заменён на плоскую шапку, «·»-разделители в футере убраны.
- **frontend-ui-engineering (Addy Osmani)**: контраст проверен скриптом `contrast-checker.py` — акцент `#1e5ba1` на белом 6.85:1, текст 14.5:1, бейджи AQI 7.1–9.4:1; цвет всегда дублируется текстом.
- **web-design-guidelines (Vercel)**: skip-link, `theme-color`, `touch-action: manipulation`, `prefers-reduced-motion`, неразрывные пробелы перед единицами измерения, `autocomplete="off"` и защита от повторной отправки в форме наблюдений.

## Публикация

Для сдачи: задеплоить `server.js` на Node-хостинг (Render, Railway, VPS — команда запуска `node server.js`, порт из `process.env.PORT`) и выложить исходники в Git-репозиторий. Формат отправки: ФИО, ссылка на сайт, ссылка на репозиторий.

## Журнал существенного применения ИИ

Проект сгенерирован ИИ-ассистентом (Kimi Code CLI) по ТЗ практического задания: структура файлов, все классы виджетов, сервер, стили и README. После генерации выполнена проверка: синтаксис и импорты модулей (`node`), запуск сервера, CRUD `/api/notes` через `curl`, отдача статики.

Оформление переработано по собранным design-skills (пять репозиториев склонированы в `design-skills/`, изучены, применены): замена градиентного хедера на плоский, доменные oklch-токены, отказ от теней в пользу рамок, табличные цифры, tinted-бейджи AQI. Контрасты проверены `contrast-checker.py` из состава skills; `--ink-faint` затемнён после проверки (3.36:1 → 4.65:1). Визуальная проверка в браузере не выполнялась ассистентом (нет инструментов скриншотов) — рекомендуется ручной прогон. Зафиксировано на 01.10.2026.
